BlockUI BlockUI blocks any piece(s) of a page, or the entire page, during Ajax calls. A "source" component blocks one or more "target" components with an overlay and custom content.

Usage modes

There are two ways to use BlockUI. The first uses the widget's JavaScript API (block() / unblock()) in onstart / oncomplete callbacks. The second, so-called autoShow mode, hooks into jQuery global Ajax callbacks so no explicit calls are needed. Components and p:ajax with global="false" do not trigger BlockUI in autoShow mode.

Some HTML elements such as table or span cannot be blocked; wrap them in a div (h:panelGroup layout="block"). Multiple blockings of the same element by different Ajax calls are tracked: the element is unblocked only after all calls have finished.
Basic usage with p:ajax

Uses the widget's block() / unblock() as onstart / oncomplete callbacks. Add a message, or page and sort the table.
AutoShow mode and more

With autoShow="true" the source component's Ajax events (see event) block the target component(s) automatically. Only events defined by p:ajax are supported. Expand, select or unselect a tree node, or click a checkbox.
Page Blocking

The entire page is blocked when the target attribute is omitted. The button blocks the whole page for the duration of the Ajax call.

Non-centered message, auto-unblock and more

A non-centered message defined by css and centerX / centerY, a styled overlay via cssOverlay, and auto-unblocking after timeout milliseconds. The whole page is blocked for two seconds.
